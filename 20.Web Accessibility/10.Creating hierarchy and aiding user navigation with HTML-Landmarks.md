In this chapter, we will learn about landmark regions — what type of content each one represents, how to define and identify them, and how to define your own custom regions using HTML and ARIA.

Most Web pages today consist of perceivable areas of content that are distinctively styled and laid out to indicate the type of content that they contain.

The typical Web page consists of:

- a header area (banner) shared across pages, and which usually contains logos, navigation links and search forms,
- a footer area shared across pages, and which contains general information about the content of the page,
- a main content area which contains the primary unique content of each page,
- and one or more sidebars which may contain any type of content that may be complementary to the main content of the page.

A sighted user can identify these areas by the way they are styled and laid out on the page. And if marked up appropriately, each of these areas can act as a landmark that can help orient screen reader users on a page.

## What is a landmark region?

![What is a landmark region](./markdown-assets/landmarks.png)

A landmark is, by definition, something (like a building, a large tree, or a statue) that is easy to see and can help a person judge where they are, and find their way to a place near it.

For example, the pyramids of Egypt are a (very!) recognizable landmark. If you were in Egypt and you saw the Pyramids, or if you were near the pyramids, you would know that you are probably in Giza on the outskirts of Cairo.

Just like real-life landmarks, **landmarks on the Web refer to recognizable key areas of a page or application.** For example, the header, main content area, and footer, are recognizable areas — or _regions_ — on most webpages.

A landmark region **helps set expectations for the type, and importance, of the content that it contains.**

Landmarks **help screen reader users orient themselves** on a page, and they enable them to navigate easily to the different areas of a page. In [the previous chapter](https://practical-accessibility.today/chapters/heading-structure/), we saw how Léonie Watson navigated her way around a website using landmark regions.

Someone using a screen reader gets their information about the page from the accessibility tree that the browser exposes. So, in order to expose page landmarks to screen reader users, we need to semantically identify these areas using HTML elements.

By identifying the landmark regions of a page, we provide users with an overview of the content of the page, similar to what someone may see by looking at the page. Doing so is required to conform to **SC 1.3.1 Info and Relationships**, which states that:

`Information, structure, and relationships conveyed through presentation can be programmatically determined or are available in text.`

Using the appropriate semantic elements that semantically identify key areas of the page is a requirement to meet this success criterion.

Furthermore, [SC 2.4.1 Bypass Blocks](https://www.w3.org/WAI/WCAG21/quickref/?showtechniques=241#bypass-blocks) exists to ensure that assistive technology users have a way to bypass repeated content and facilitate page navigation. Using proper landmark elements is one way to meet this criterion.

According to [WebAIM’s 9th screen reader user survey](https://webaim.org/projects/screenreadersurvey9/#landmarks), **more than 25% of screen reader users reported using landmark regions very often to find their way around a page.**

Every screen reader has at least one command or gesture for navigating between landmarks.

**Landmarks are primarily useful for screen reader users.** But they can also be useful to savvy keyboard users who may use [a browser extension that enables landmark navigation](https://github.com/matatk/landmarks) via keyboard or a pop-up menu.

## Types of landmarks & their associated HTML elements

There are eight types of landmark regions defined by eight ARIA roles. Each type sets the expectation for the type and importance of the content that it contains. For each landmark, an HTML element exists that semantically represents that landmark and implicitly maps to its ARIA role.

### The banner landmark

The banner landmark region usually appears at the beginning of each page, and is typically repeated across pages of a website. It contains global, site-oriented content, such as the company logo, main site navigation, user login links, and a global search component. Content that is page-specific should normally be contained in another region rather than within in the banner landmark.

A website should ideally expose only one banner region.

To create a banner region, you should use the `<header>` element. The HTML `<header>` element has an implicit banner role and is, therefore, exposed as a banner region to screen readers… **but only when it is a direct child of the `<body>` element**. It is not meant to be exposed as a banner region when it is a child of other sectioning elements (like `<article>`, `<section>`, etc.).

`<header>` is likely going to be the first child of the `<body>`:

```html
<body>
  <header>This is the banner region.</header>
  <!-- other regions defined here -->
</body>
```

You `can` use the `<header>` element to semantically group content within other sectioning elements, but it won’t be exposed as a banner landmark in those contexts (which is intentional).

```html
<body>
  <header>This is the banner region.</header>
  <section>
    <header>
      This header is not exposed as a banner
      region.
    </header>
  </section>
</body>
```

### The `navigation` landmark

A `navigation` landmark is a region that contains a collection of navigational elements -- usually link -- for navigation within a website.

The HTML `<nav>` element has an implicit `navigation` role. This means that you can create a navigation landmark using the `<nav>` element.

```html
<nav>
  <!-- this is a navigation landmark -->
</nav>
```

You can create as many navigation regions as is needed on a page.

### Identifying multiple navigation landmarks on the page

To help the user identify the purpose of each navigation, **each navigation should have an accessible name (or label) that describes its purpose to the user.**

You can provide an accessible name to a landmark region in two ways:

1. Using the `aria-label` attribute. The value of the attribute will be used as the accessible name(label) of the navigation:

   ```html
   <nav aria-label="Site">
     <!-- navigation links -->
   </nav>

   <nav aria-label="Breadcrumbs">
     <!-- navigation links -->
   </nav>
   ```

2. Using the aria-labelledby attribute. The aria-labelledby attribute allows you to use an existing element on the page as a label for another element. So, for example, if there is a heading on the page that describes the navigation’s purpose, you can use that heading as a label for the navigation:

   ```html
   <nav aria-labelledby="categories_label">
     <h2 id="categories_label">Categories</h2>
     <!-- list of content categories -->
   </nav>
   ```

We will learn all about providing accessible names to elements using HTML and ARIA, as well as best practices for doing so, in [another chapter](https://practical-accessibility.today/chapters/accName/).

### The main landmark

The main landmark designates the primary content of the page.

As such, there should only be one main landmark region. Having more than one main region introduces usability issues. Having multiple main landmarks is confusing, and may disorient users trying to find their way to the primary content of the page. (If there is more than one main region, _which_ one contains the primary content of the page?)

The HTML `<main>` element has an implicit main landmark role. And it should be a direct child of the `<body>` element:

```html
<body>
  <header>This is the banner region.</header>

  <main>
    Here goes the primary content of the page.
  </main>
</body>
```

### The contentinfo landmark

The contentinfo landmark **contains information about the parent document.**

On a typical webpage, this region designates the footer at the bottom of the page, and, like the banner region, is usually repeated across the pages of the website. It typically contains copyright information, links to privacy and accessibility statements, and other informational content.

In most browsers, the `<footer>` element is mapped to the contentinfo role when it is scoped to the `<body>` element. `<footer>` will not be exposed as a contentinfo region if it is a child of the other sectioning elements.

```html
<body>
  <header>This is the banner region.</header>

  <main>
    Here goes the primary content of the page.
  </main>

  <footer role="contentinfo">
    This is the contentinfo region.
  </footer>
</body>
```

`Note that some versions of Safari prior to Safari 13 didn’t expose a <footer> as a contentinfo region unless the contentinfo role was explicitly assigned to it using ARIA (role="contentinfo"), but that is no longer necessary today.`

Just like the `<header>` element, you can use the `<footer>` element to semantically group informational content within other sectioning elements, but it currently won’t be exposed as a contentinfo landmark region in those contexts (which is, again, intentional).

```html
<body>
  <header>This is the banner region.</header>

  <main>
    Here goes the primary content of the page.

    <!-- this footer is not exposed as a contentinfo landmark -->
    <footer>
      I am a footer not scoped to the body.
    </footer>
  </main>

  <footer>This is the contentinfo region.</footer>
</body>
```

### The complementary landmark

The complementary landmark contains secondary information that is complementary to the main content. It should be related to the main content, but should also be easily understood without it. Content that does not fit this description is better contained in another type of landmark.

Complementary content is usually presented as sidebars or call-out boxes. A common example of complementary content is a list of related articles in a blog post.

To create a complementary landmark, use the `<aside>` element.

```html
<body>
  <header>This is the banner region.</header>

  <main>
    Here goes the primary content of the page.

    <aside>
      <h2>Title for this complementary area</h2>
      This is secondary information related to the
      `main` content of the page.
    </aside>
  </main>

  <aside>
    <h2>Title for another complementary area</h2>
    This is another secondary information area.
  </aside>

  <footer>This is the contentinfo region.</footer>
</body>
```

A complementary landmark region should be either a sibling or a child of the main landmark. And a good practice is to label the content in an `<aside>` using a descriptive heading.

You may create more than one complementary landmark on a page. Similar to the navigation landmark, if you do create more than one complementary landmark, assign each of them an appropriate name that identifies its purpose. When a heading is present, you can expose that heading as the name for the `<aside>` using the aria-labelledby attribute:

```html
<aside aria-labelledby="aside_title_ID">
  <h2 id="aside_title_ID">
    Title for this complementary area
  </h2>
  This is secondary information related to the
  `main` content of the page.
</aside>

<aside aria-labelledby="second_aside_title_ID">
  <h2 id="second_aside_title_ID">
    Title for another complementary area
  </h2>
  This is another secondary information area.
</aside>
```

A good rule of thumb is to try to limit your use landmarks on a page, and only expose the landmarks that will facilitate user navigation without adding unnecessary noise. Surfacing too many landmarks has a counter-effect: it decreases the user’s efficiency in finding and navigating to important areas of the page.

### The form landmark

Since `<form>`s are an important part of a webpage or application, they can expose their own landmark region.

Every form should ideally have a visible label that describes what the form is for. This label may then be used to provide an accessible name for the form using aria-labelledby:

```html
<form
  action=""
  aria-labelledby="signup_form_label">
  <h2 id="signup_form_label">Sign up</h2>
  <!-- form controls here -->
</form>
```

The `<form>` element is **not exposed as a form landmark by default**. It is only exposed as a form landmark **when it is given an accessible name**. Not all forms need to be exposed as landmarks.

Again, a good rule of thumb is to try to limit your use landmarks on a page — only expose the landmarks that will facilitate user navigation without adding unnecessary noise. If the form is the primary content of a page, exposing it as a landmark will not be necessary.

### The search landmark

A search landmark represents a collection of elements that, combined, create a search facility.

Search functionality is important because it offers users a way to find content on a website without needing to understand or navigate through the structure of the site. This makes finding content on the site easier and more efficient. This is why search is a landmark separate from the form landmark.

On most websites, a search landmark contains elements (typically form controls) that produce search functionality.

For many years, HTML had no native element that mapped to the search landmark role. Instead, to create a search landmark, we needed to explicitly assign the search role to the element we wanted to expose as a search landmark — which was usually either a `<form>` element or a `<div>` that contains search components:

```html
<form
  role="search"
  action=".."
  aria-labelledby="search_label">
  <label for="search">Search articles</label>
  <input type="text" id="search" />
  <button type="submit">Search</button>
</form>

<!-- or -->

<div role="search">
  <label for="search">Search articles</label>
  <input type="text" id="search" />

  <ul id="search-results">
    ..
  </ul>
</div>
```

Today, you can create a search landmark using the HTML `<search>` element.

The `<search>` element maps to the search landmark role and represents a part of a document or application that contains **a set of form controls or other content related to performing a search or filtering operation.** This could be **a search of the web site or application; a way of searching or filtering search results** on the current web page; or a global or Internet-wide search function. [(HTML specification)](https://html.spec.whatwg.org/multipage/grouping-content.html#the-search-element)

For example, the `<search>` landmark may contain a submittable search form:

```html
<!-- search landmark containing a submittable form -->
<search>
  <form action="search.php">
    <label for="query">Find an article</label>
    <input id="query" name="q" type="search" />
    <button type="submit">Go!</button>
  </form>
</search>
```

…or a search input field that, instead of submitting to the server, dynamically shows search results as the user types in the field:

```html
<search>
  <label>
    Find and filter your query
    <input type="search" id="query" />
  </label>

  <section>
    <h3>Results found:</h3>
    <ul id="results">
      <li>...</li>
      ...
    </ul>

    <output id="no-results"
      ><!-- When no results are found, render the no results message here --></output
    >
  </section>
</search>
```

## Identifying multiple search landmarks on the page

A page may also contain more than one search landmark.

In the following example, the page has two search features. The first is located in the web page’s header and serves as a global mechanism to search the web site’s content. Its purpose is indicated by its specified title attribute. The second is included as part of the main content of the page, as it represents a mechanism to search and filter the content of the current page. (Content filtering is a type of search.) The content filtering search feature contains a heading to indicate its purpose.

```html
<body>
  <header>
    ...
    <search> ... </search>
  </header>
  <main>
    <h1>Hotels near your location</h1>
    <search>
      <h2>Filter results</h2>
      ...
    </search>
    <article>
      <!-- search result content -->
    </article>
  </main>
</body>
```

To identify the purpose of each search feature to assistive technology users like screen reader users, you may give each `<search>` element an accessible name.

When there is a heading present that indicates the search’s purpose, use the aria-labelledby attribute to associate that heading with its corresponding `<search>` element:

```html
<body>
  <header>...</header>
  <main>
    <h1>Hotels near your location</h1>
    <search aria-labelledby="filters-label">
      <h2 id="filters-label">Filter results</h2>
      ...
    </search>
    <article>
      <!-- search result content -->
    </article>
  </main>
</body>
```

When there is no element on the page to use as an accessible name, you can either use the aria-label attribute:

```html
<body>
  <header>
    ...
    <search aria-label="Site"> ... </search>
  </header>
  <main>...</main>
</body>
```

…or you can create a hidden text label and also associate it with the `<search>` landmark using aria-labelledby:

```html
<body>
  <header>
    ...
    <search aria-labelledby="site-search">
      <span id="site-search" hidden></span>
      ...
    </search>
  </header>
  <main>...</main>
</body>
```

We will learn all about this technique, as well as other methods for providing accessible names to HTML elements, in [another chapter.](https://practical-accessibility.today/chapters/accName-techniques/)

### The generic region

The last type of landmark is the generic region landmark.

A region landmark is defined as “a perceivable section containing content that is relevant to a specific purpose and sufficiently important that users will likely want to be able to navigate to the section easily and to have it listed in a summary of the page.”

In other words, the region landmark is suitable for content that you deem important enough to the user to surface it as its own landmark so that the user can quickly access it when they need it.

Since HTML provides meaningful landmark elements for various types of content, you should use those landmarks, and **limit the use of the region role to sections of content that have a different purpose than that defined by the other landmark regions.**

As we mentioned before, the rule of thumb is to try to limit your use landmarks on a page, and only expose the landmarks that are important and that improve the usability of a page.

Because the region landmark is a high-level, generic landmark, it does not describe the content it contains. As such, **you need to identify its purpose by giving it an accessible name that describes the purpose of the content inside of it**. Preferably, the region should have a visible heading that you reference using aria-labelledby.

```html
<!-- this section is exposed as a landmark region -->
<section aria-labelledby="console_label">
  <h2 id="console_label">Editor</h2>
  ..
</section>
```

There is no HTML element that is exposed as a region landmark by default. But the `<section>` is exposed as a region when it is provided with an accessible name. So, to create a region landmark, use the `<section>` element and give it an accessible name.

You may also repurpose another element (such as a `<div>`) and explicitly assign the region role to it. Either way, an accessible name is required to surface the region as a landmark.

```html
<!-- this div with an explicit region role is exposed as a landmark region -->
<div
  role="region"
  aria-labelledby="console_label">
  <h2 id="console_label">Editor</h2>
  ..
</div>
```

That being said, `<section>` is the most appropriate element to use here since it has region semantics baked in, and will be exposed without the need of an additional ARIA attribute.

So, even though `<section>` doesn’t affect the document outline (as we learned in the previous chapter), **it has useful, meaningful semantics that you can use for the purpose of creating a ‘custom’ landmark region..**

## Creating custom landmark regions

Custom regions are particularly important when the contents of a page don’t fit into any of the landmark regions that are already available. For example, if you’re building a Web application that contains key areas that are not semantically described by the readily-available landmark regions.

I used custom landmark regions when I created the user interface of an online code editor. The code editor consisted of three main areas: the editor, the settings panel, and the console. Each of these areas got its own custom region because they are not semantically described by any of the available landmark regions.

So, to expose an area as a landmark region:

1. wrap the content in a `<section>` element (or an equivalent element with an explicit role="region"), and

2. give the section an accessible name.

```html
<section aria-labelledby="editor_label">
  <h2 id="editor_label">Editor</h2>
</section>

<section aria-labelledby="settings_label">
  <h2 id="settings_label">Settings</h2>
</section>

<section aria-labelledby="console_label">
  <h2 id="console_label">Console</h2>
</section>
```

You can then see the region exposed in something like the Landmarks menu in VoiceOver’s web rotor.

Again, **limit your use of custom landmarks.** Promoting too many sections into landmarks has a counter-effect: it decreases the user’s efficiency in finding and navigating to important areas of the page. If _all_ sections of the page are marked as important, then the really important regions will not stand out anymore.

## Adding landmarks to an existing document using ARIA

If you have one or more existing websites that you want to add landmarks to but you cannot modify the markup or elements used, you may use the ARIA `role` attribute to add landmark semantics to existing elements.

ARIA provides role values for all landmark types:

- banner
- nav
- main
- contentinfo
- aside
- form
- search
- region

If you’re dealing with a webpage that uses `<div>`s all over, you may define landmark areas by adding landmark roles to the appropriate `<div>`s:

```html
<body>
  <div role="banner" class="header">
    <div>more header stuff here</div>
  </div>
  <div role="main" class="content"></div>
  <div role="complementary" class="sidebar"></div>

  <div
    role="contentinfo"
    class="site-footer"></div>
</body>
```

Use the visual design of your website to guide your choice of landmarks. The purpose of doing so is ensuring that the information that is available visually is also semantically exposed via HTML elements. (This is the purpose of using semantic HTML! )

By providing the right semantics, screen readers can create an alternate presentation of the page that conveys the same structure and meaning that is conveyed visually with CSS.

## Visualizing a page’s landmark regions

You can visualize the landmark regions on a page to get a sense of whether or not they correctly represent the content inside of them using WebAIM’s [WAVE browser extension](https://wave.webaim.org/extension/).

The WAVE extension allows you to evaluate web content for accessibility issues directly within your browser.

After installing the extension, you can run it by clicking the WAVE icon to the right of the browser address bar. The extension displays the result of the evaluation within the context of the page’s viewport, in a sidebar at the left side of the page.

In addition to reporting existing accessibility issues such as insufficient color contrast, images missing alternative text, and so on and so forth… the **Structure** tab provides a structural representation of the page, which includes all the landmarks used on the page, as well as the heading structure within each landmark.

Visualizing the page’s structure will give you important insight into how the page is exposed to screen reader users, so you can fix or remediate the page structure when it does not properly represent the content layout and hierarchy.

## Summary

By using landmarks appropriately, you can dramatically improve the navigation experience of your website for screen reader users.

Don’t over-use landmarks, though. Use fewer landmarks to provide a concise overview of the content of the page. Then utilize headings to create a more fine-grained navigation within a particular area of the page.

A good rule of thumb is to **use as few landmarks as possible, but ensure that all of the content on the page is contained within a meaningful landmark region.**
