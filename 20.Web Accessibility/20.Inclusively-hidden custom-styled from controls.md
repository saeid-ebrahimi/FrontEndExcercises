# Case Study: Inclusively-hidden custom-styled form controls

Using native HTML controls has many practical benefits. Not _only_ do browsers provide keyboard interactions for free, but they also provide default styling for the different states of a control. For example, checkboxes and radio buttons have visual styles indicating when they are checked or selected. The browser also grays out (or dims) controls when they are disabled, and adjusts their colors to remain accessible in Forced Colors environments.

But default browser styles leave much to be desired. Not only are they inconsistent across browsers and platforms, but their aesthetics usually don’t match those of our design and brand. While it is possible to style form controls such as checkboxes and radio buttons more liberally [using CSS today](https://css-tricks.com/custom-styling-form-inputs-with-modern-css-features/), there may be times when using CSS alone is not enough. Over the years, we’ve been hacking our way around form styling limitations by hiding the native controls and replacing them with what is essentially an image of the control. However, most of the implementations of this technique haven’t been entirely accessible.

In this chapter, we’re going to demonstrate how to hide a native form control while ensuring it remains accessible to users of assistive technologies — **particularly mobile screen reader users navigating by touch**. We will create a custom-styled checkbox to demonstrate the process, but **the technique we will learn is applicable to any other interactive form control** that you may want to replace with an image.

So, let’s get started!

## Setting the foundation in the markup

We’re going to use an inline `<svg>` image to create our custom checkbox styles.

Inlining the SVG is the most flexible way to embed it because it gives you full control over the contents of the SVG, so you can access and style them from your stylesheet. Plus, inline SVG is animatable, and it is more flexible in terms of adapting to Forced Colors modes like Windows Contrast Themes (which we will learn all about in [another chapter](https://practical-accessibility.today/chapter/forced-colors-mode/)).

We’re going to inline the `<svg>` after the checkbox in the markup so that it is easier to select and style using the CSS adjacent sibling selector (which we’re going to do in a few minutes).

To increase the checkbox’s interactive area, we’re going to place the checkbox (as well as the `<svg>`) inside its `<label>`.

```html
<label for="c-checkbox" class="c-custom-checkbox">
  <input type="checkbox" id="c-checkbox" />
  <svg
    width="32"
    height="32"
    viewBox="-4 -4 39 39"
    aria-hidden="true">
    <!-- The background -->
    <rect
      class="checkbox__background"
      width="35"
      height="35"
      x="-2"
      y="-2"
      stroke="currentColor"
      fill="none"
      stroke-width="3"
      rx="6"
      ry="6"></rect>
    <!-- The checkmark-->
    <polyline
      class="checkbox__checkmark"
      points="4,14 12,23 28,5"
      stroke="transparent"
      stroke-width="4"
      fill="none"></polyline>
  </svg>

  <span>Add an accessibility statement</span>
</label>
```

Since the `<svg>` is going to replace the checkbox **only visually, the checkbox itself needs to remain accessible to screen readers**. And since the checkbox is going to be exposed to screen readers, the `<svg>` can be hidden using `aria-hidden="true"` because its purpose, at this point, becomes purely presentational.
