When you visit a library, you browse and recognize books by their titles. If a book doesn’t have a title, you won’t be able to know what the book is about unless you open that book and _read_ some of its content.

![Bookshelves in a library.](/markdown-assets/28.1.library.png)

Now imagine your browser is a library. And each open tab is a book. Page titles identify webpages in the browser similar to how book titles identify books in a library. Without descriptive page titles, a user can’t know which page is open in a tab and what the content of the page is about, unless they navigate to that page and browse its contents.

## Page titles aid in navigation

So, page titles are important because **they help a user navigate among open tabs within their browser.** Most users have multiple tabs open at a time. And it is easier for them to jump between pages when each page has a unique, descriptive title.

Browsers display the title of a page in the window title bar, or as the name of the tab in which the page is open. When no page title is present, most browsers will display the full URL of the page instead.

![A browser window with three open tabs. Each tab is displaying the title of the page that is open in it.](/markdown-assets/28.2.window-tabs.png)

When a screen reader user navigates between tabs, the very first thing that they hear is the title of the page that is open in that tab. It identifies what the page is, and often sets the expectation for the contents of the page.

For example, here I have four tabs open in Safari. I’m going to fire up VoiceOver and navigate between the tabs in the browser using my keyboard. The first page on the left — the fourth page I navigate to, is a demo page that has no title. Notice how when I navigate to that page, VoiceOver doesn’t announce a title, so you can’t tell what the page content is about without navigating _into_ the page.

## Page titles are a WCAG requirement

Providing unique page titles that describe the topic or purpose of a page is a WCAG requirement.

[Success Criterion **2.4.2 Page Titled (Level A)**](https://www.w3.org/WAI/WCAG21/quickref/#page-titled) states that:

> **Web pages have titles that describe topic or purpose.**

The intent of this Success Criterion is to help users find content and orient themselves within it. Titles identify the current location without requiring users to read or interpret page content.

A descriptive title allows a user to easily identify what webpage they are using. Consequently, **the title also allows users to tell when the page has changed (because it changes when the page does).** (I want you to keep this piece of information in the back of your head because we’re going to come back to it in another chapter.)

## Providing a descriptive title using the HTML title element

To provide a title to the page, you need to use the `<title>` element.

The `<title>` element defines the page title and is always used within the page’s `<head>` block:

```html
<html>
  <head>
    <title>
      This string of text describes the page
    </title>
  </head>
  <body>
    <!-- ... -->
  </body>
</html>
```

Since page titles are a WCAG requirement, most automated accessibility checkers will tell you when the page is missing a `<title>` or when the `<title>` is empty. But **an automated checker will not be able to tell you if the title is descriptive.** You should manually check that the title of a page describes the primary purpose of the page.

The title of each webpage should:

- Identify the subject or the primary purpose of the page;
- make sense when read out of context (for example by a screen reader or in a site map or list of search results);
- not contain special characters that may cause unnecessary weird announcements (for example, the “vertical bar” that is commonly used in page titles and that we heard an example of in the previous section);
- be short and concise.

Page titles should be unique within the site. That being said…

## Identify the site to which the webpage belongs

It is often helpful to identify the site to which the page belongs to within the page’s title. For instance, an online publication may append the name of the publication to all of its pages. For example, here is what the page titles for the pages on [A List Apart](https://alistapart.com/) look like:

![A browser window with four A List Apart pages open in tabs. Each tab is displaying the title of the page, and each title has ‘– A List Apart’ appended to it.](/markdown-assets/28.4.the-list-apart.png)

Doing so enables users to identify the site to which the webpage belongs, as well as identify the relationship between the current webpage and other webpages on the website.

If you do this on your website, make sure the unique title of each page comes first; this ensures that the most important identifying piece in the title is visible in the browser’s tab when multiple tabs are open, and that the primary purpose of the page is announced by a screen reader first. This provides a far better experience than having to listen to the name of a website before the unique page title, for every page a user navigates to in the same website.

In a page template, the markup may look something like this:

```html
<title>{ { title } } – Site Name</title>
<!-- Where `{ { title } }` is the unique title of each page that uses this template. -->
```

Where `{ { title } }` is the unique title of each page that uses this template. For sighted users, a website’s favicon serves as a further visual cue for identifying which site it is.

## The page title and `h1` should typically match

The `<title>` and the `<h1>` heading of a page serve a similar purpose. The `<title>` identifies the page within a website and sets expectations for the content it contains; and the `<h1>` heading of the page describes the primary content of the page.

As such, the `<h1>` and the unique part of the `<title>` should be identical. The exception to this rule is usually on the homepages of websites, where the `<h1>` usually does not match the homepage’s title. For example, here is the personal website of Léonie Watson, Director of [Tetralogical](https://tetralogical.com/). Léonie matches the `<h1>`s on her pages to the unique part of each page’s `<title>`. The only exception is the homepage, where the (visually-hidden) `<h1>` describes the primary content of the page, which happens to be a list of her latest blog posts.

## Outro

In addition to providing a descriptive title to identify the page, screen readers and other Text-To-Speech software need to know the language of the page so that they can properly speak the content of the page to the user. And that’s what we’re going to discuss in the next chapter. See you in a bit!
