They say a picture is worth a thousand words. That’s why we use photos and images all the time in our daily lives to communicate information, or to express an idea or an emotion…

Whatever it is we try to communicate through an image on the Web, it can only be visually perceived by someone who can see the image. If someone can’t see the image, how do they know what we’re trying to say through it?

Some Text-to-Speech (TTS) assistive technology users like blind screen reader users who can’t see what’s on screen rely on text to understand and operate digital content. TTS software reads all text that’s on the screen to the user or renders it as Braille for users using Braille displays.

When you use an image instead of text to communicate information, these assistive technologies won’t be able to convey that information to the user unless you provide a **text alternative of that information.** That’s why alternative text descriptions of images are so important.

## What is alternative text (alt text)?

The alternative text of an image — also commonly known as the _`alt`_ text — is text that **describes an image to users who can’t see it, so that they can understand its purpose.**

## Why is alt text so important?

Just like user interface components need names to identify their purpose, images need alt text to identify their purpose when they have one. If the image is meant to communicate a piece of information, for example, you include that information in the image’s alt text. **This makes alt text part of the primary content of a page.** Without alt text, users who can’t see the image will not get the same information as sighted users, and may therefore not be able to fully understand the content or perform a certain task.

- **Alt text is important for people with little or no vision** who use screen readers or other TTS assistive technologies to browse the Web and who rely on text to understand a page.

- It is also important for people browsing with speech recognition. When an image doesn’t load, these users can use the image’s alt text in the voice command to trigger the action that the image may represent. (More on this later.)

- Alt text is **useful for SEO**. Search engines are better able to index images when they have text alternatives.

- It is also important **for users on slow networks** who have turned images off to save data, or for whom images simply won’t load because their network is slow.

When an image doesn’t load, browsers will display a placeholder with the alt text instead (when it is present), so the user can perceive the same information that the image is meant to convey. Without the alt text providing this information, they may not be able to fully understand the content.

![A broken image placeholder showing a broken image icon sitting next to the alt-text of the image.](/markdown-assets/30.1.alt-image-usage.png)

### Alternative text (where it is needed) is a WCAG requirement

The very first Success Criterion in the Web Content Accessibility Guidelines states that:

> **All non-text content that is presented to the user has a text alternative that serves the equivalent purpose…**
>
> — [WCAG SC 1.1.1 Non-text Content, Level A](https://www.w3.org/WAI/WCAG21/quickref/#non-text-content)

I want to emphasize the last part of this sentence: that the image’s text alternative needs to **serve an equivalent purpose,** because the value of the text alternative as well as its effectiveness is determined by how well it does that — by how well it serves the image’s equivalent purpose.

In this chapter, we’re going to discuss best practices to help you write more effective alt text for images.

## The alt attribute

To provide an alt text for an image in HTML, you should use the alt attribute on the image you want to provide the alternative text for.

For example:

```html
<img
  src="/path/to/image.jpg"
  alt="A baby white-spectacled bulbul dozing on Sara’s hand." />
```

The `alt` attribute is HTML’s **native image naming mechanism.** Unless it’s missing, and unless you use ARIA to override it, the value of the `alt` attribute will be used by the browser as an accName for the `<img>`.

![Screenshot of the Chrome DevTools Accessibility panel showing an image’s alt attribute value used as an accessible name for the image.](/markdown-assets/30.2.image-accessibility.webp)

_The alt attribute is sometimes referred to by some developers as a tag instead of an attribute. In HTML, a tag is used to create an element. Whereas an attribute is used to represent an attribute of that element. alt is not a tag; it is an attribute of the `<img>` element._

**The `alt` attribute only works on the `<img>` element.** It won’t work on any other element, even if that element that has been explicitly assigned an img role using ARIA.

```html
<!-- this doesn't work -->
<div
  role="img"
  alt="this is the image description"></div>
```

If, for any reason, you ever need to expose another HTML element an image, you can give it an accessible name using `aria-label` or `aria-labelledby`. We’ll see an example of that in another section.

If you use the `<picture>` element to create a responsive image, the browser will use the alt attribute specified on the (fallback) `<img>` element inside of it as a text alternative for whichever image is rendered.

```html
<picture>
  <source
    media="(min-width: 1024px)"
    srcset="photo--landscape.jpg" />
  <img
    src="photo--portrait.jpg"
    alt="The photo's text description" />
</picture>
```

### Does your image need alternative text?

The alternative text is meant to provide equivalent purpose for images so that users who can’t see the images can still access the primary information communicated by them. But not _all_ images are meant to communicate information. So **not all images _need_ an alternative text.**

If the image contains content that is considered as decoration, or if the image does not communicate information that is essential for understanding the content around it, it doesn’t _need_ to have an alternative text. Though, sometimes, you may give it an alt text anyway. More on this later.

Nevertheless, **the `alt` attribute must always be specified** on an image. Regardless of whether the image is essential or not, you must _always_ give it an _alt_ attribute.

This brings us to: when does an image not need a text alternative? And if the `alt` attribute must always be present, what should its value be?

### Types of images and their alternative texts

The _value_ of the `alt` attribute is context-dependent; and it also depends on the type of the image, and on what it is intended to represent.

Images can be categorized into five different types:

- Unessential images.
- Images of text.
- Complex images.
- Functional images.
- Informative images.

#### Unessential images (decorative or redundant)

Unessential images are images that are not meant to communicate information that contributes to the understanding of a page. These images are usually either **decorative** or **redundant.**

**A decorative image** is an image used for decorative purposes — its only purpose is to add visual decoration to the page. Examples of decorative images range from decorative backgrounds, to border images, and images added to articles or blog posts for visual styling purposes only.

![Screenshot of the Codrops articles page showing a list of article entries with decorative poster images.](/markdown-assets/30.3.decorative-image.webp)

_Many article entries on online publications are typically accompanied with poster images that communicate no information. These images need no alternative text to describe them._

**A redundant image** is an image that is not decorative, but it is still unessential to the understanding of the content. It is usually supplemental to what has already been presented in text.

Supplemental icons sitting next to text in buttons or links are an example of redundant images. Of course, not all icons sitting next to text are supplemental, but when the text of the button or link is sufficient to provide its accessible name, and the design incorporates an icon for visual purposes only, the icon in this particular case would be unessential, and does not need to be exposed to the user. For example, user interface buttons that include an icon to visually represent the function of the button which is already identified by its text label.

```html
<button>
  <!-- this img is supplemental, so it does not need an alt text; 
         so, it's alt attribute is ‘nulled’ -->
  <img src="/path/to/like-icon.png" alt="" />
  Like
</button>
```

When an image is unessential, the alt attribute should often be left empty — or ‘nulled’. (There may be exceptions; we’ll discuss examples of this later.)

When the alt attribute is empty, the image should be ignored and not announced by screen readers.

If the value of the alt attribute contains so much as an empty space, it is no longer considered empty and its presence is announced by screen readers, except that, in this case, it won’t have a meaningful and descriptive name.

```html
<!-- this image will be exposed but without a meaningful description -->
<img src="..." alt=" " />
```

Using an empty alt attribute on an `<img>` has the same effect as using `role="none"` or `aria-hidden="true"` on it.

```html
<!-- these are equivalent -->
<img src="..." alt="" />
<img src="..." alt />
<img src="..." alt="something" role="none" />
<img
  src="..."
  alt="something"
  aria-hidden="true" />
```

Any of these techniques can be used to hide a decorative or redundant image from assistive technologies, while still passing WCAG Success Criterion 1.1.1 Non-Text Content, which states that:

> **If non-text content is pure decoration, is used only for visual formatting, or is not presented to users, then it is implemented in a way that it can be ignored by assistive technology.”**

**You should not use these techniques to hide images that serve a meaningful purpose on the page or communicate relevant information to the user.**

Sometimes, it may be appropriate to communicate the presence of an image even if it is considered unessential. Some users prefer to know when there is an image provided, even if it doesn’t add important meaning to the primary content of the page.

Whether or not you communicate the presence of an unessential image would depend on the context in which it is used.

For example, this chart on the [ESLint website](https://eslint.org/) shows where the ESLint donation money is spent. The image is a graphical visualization of the text on the left side of the graph. So, it is redundant.

![Screenshot of the donation page on the ESLint website. A pie chart in the right column visually represents the places where the donation money is spent. The spending information is written in more detail in plain text in the left column.](/markdown-assets/30.4.redundant-image.webp)

When I implemented the design for this website, I did provide an alt text for this image; but the description only described what the chart represents, without describing the actual text content in it. That content is already represented by the text sitting next to it.

Once again, whether or not you communicate the presence of an image will depend on the context in which it is used. I prefer to let a user know when an image is provided if it helps them form a clearer image (pun not intended) of what is present on the page.

The ESLint pie chart is an example of a simple chart, with not a lot of information represented in it. And it so happened that the text on the page already described the information that the image is meant to represent. But there are often times where an image will communicate information that is essential to understanding the page, and that is not already provided in plain text elsewhere on the page.

There are two types of images that communicate essential text content: images of text, and complex images.

### Images of text

An image of text is essentially text that is represented as an image instead of actual text elements. For example, this is an image of text. Similar images can be commonly seen on e-commerce websites announcing promotional offers or seasonal discounts:

![Extra 20% off. Extra 15% or 10% off select sale & clearance items. Excludes specials. Code: SAVE.](/markdown-assets/30.5.text-image.webp)

Images of text are commonly used on social media platforms, especially recently with the proliferation of AI-generated text content, such as text generated by [ChaptGPT.](https://openai.com/blog/chatgpt)

When an image is an image of text, **the `alt` value must contain the same words as the image itself.**

```html
<img
  src="../path/to/image-of-text.png"
  alt="Extra 20% off. Extra 15% or 10% off select sale & clearance items. Excludes specials. Code: SAVE." />
```

Images of text are one of the few examples where providing long alt text may be necessary to represent the information in the image.

Ideally, you should not have images of text. Try to **avoid images of text and use actual text elements styled with CSS to get the presentation that you want instead.**

When text is presented as an image instead of actual text elements, it will be much more difficult, if not impossible, for the user to adjust the presentation of the text (such as text size, color, line spacing, font family, etc.). This, in turn, could make the text harder for them to read. This is particularly relevant for:

- People with low vision (who may have trouble reading the text with the font family, size and/or color you are using),
- People with visual tracking problems (who may have trouble reading the text with the line spacing and/or alignment you are using),
- People that have cognitive disabilities that affect reading.

Real text is more flexible: it can be resized without losing clarity, and background and text colors can be modified to suit the reading preferences of the user.

WCAG [Success Criterion 1.4.5 Images of Text (Level AA)](https://www.w3.org/WAI/WCAG21/quickref/#images-of-text) states that:

> **If the technologies being used can achieve the visual presentation, text is used to convey information rather than images of text except for the following:**
>
> - **Customizable: The image of text can be visually customized to the user’s requirements;**
> - **Essential: A particular presentation of text is essential to the information being conveyed.** > **Note 1: Logotypes (text that is part of a logo or brand name) are considered essential.**

[Success Criterion 1.4.9 Images of Text (No Exception) (Level AAA)](https://www.w3.org/WAI/WCAG21/quickref/#images-of-text-no-exception) states that:

Images of text are only used for pure decoration or where a particular presentation of text is essential to the information being conveyed.

Note 1: Logotypes (text that is part of a logo or brand name) are considered essential.

In other words, the AAA version of this criterion states that text should be actual text, not images of text, unless it’s decorative or part of a logo, for example.

Both of these success criteria are meant to enable people who require a particular customization of text to be able to adjust the text as they need. Depending on the level of conformance you’re working towards, you may use images of text but probably only for very rare use cases.

### Complex Images

Some images of text represent more complex information — more than can be conveyed in a short phrase or sentence. For example graphs, charts and infographic, or images of maps.

When the image of text is complex, the text alternative will often need to be accompanied by either **(1) a more extended description** of the image’s content, **or (2) an alternative presentation** of the image’s content.

There is more than one way you can provide the extended description of the image’s content. Which way you use will depend on how the extended description is formatted: does the description need to be structured? can it be flattened to a string of text and associated with the image using aria-describedby? Is the alternative presentation of the image’s content (i.e. the actual text content of the image) available on another page that you may link to?

I worked on the Khan Academy 2018 annual report back in 2019. The report contained, by nature, a lot of data, and utilized graphs and charts to represent that data.

![Screenshot of the Khan Academy 2018 Annual report website. A chart visually represents the Association between use of Khan Academy and 2018 Smarter Balanced Assessment mathematics score, compared to students with no use.](/markdown-assets/30.6.Screenshot%20of%20the%20Khan%20Academy%202018%20Annual%20report%20website.webp)

_There were many kinds of charts and infographic on the Khan Academy 2018 annual report website._

For performance as well as flexibility considerations, we used SVG to create the charts, and I embedded them on the page using the `<object>` element, which is one of seven ways SVGs can be embedded on a page.

```html
<h4 id="long_beach">
  Association between use of Khan Academy and 2018
  Smarter Balanced Assessment mathematics score,
  compared to students with no use
</h4>

<object
  type="image/svg+xml"
  data="/images/revenue.svg"
  tabindex="-1"
  role="img"
  aria-labelledby="long_beach"
  aria-describedby="revenue_desc">
  <p id="revenue_desc">
    $24,678,765 or 56.5% of our revenue source
    came from foundation and individual gifts.
    $10,112,801 or 23.1% of revenue was earned
    income. $2,372,683 or 5.4% of our revenue
    source came from corporate gifts. $5,304,592
    or 12.1% of revenue came from community
    giving. 1,235,040 or 2.8% came from other
    sources.
  </p>
</object>
```

When you use the `<object>` element, you can provide content between its opening and closing tags to be used as a fallback for when the linked image doesn’t load. This was a perfect opportunity to feed two birds with one scone:

1. Provide a text presentation of the data presented in the chart as a fallback, and
2. associate that text with the image (`<object>`) so that it is presented to screen reader users as an extended description of the chart.

The `<object>` element is not announced as an image by default. `role="img"` communicates the nature of the image to the user.

Remember when I mentioned earlier that the `alt` attribute only works on the `<img>` element? And that if you need to expose another element as an image then you would need to use `aria-label` or `aria-labelledby` to provide the alternative text for it?

The `aria-labelledby` attribute provides the name for the image in this case because alt doesn’t work on the `<object>` element, even if it has been assigned an `img` role using ARIA.

And `aria-describedby` provides the longer description for the data inside the image.

Another approach that you may consider for providing extended image descriptions is using the `<details>` and `<summary>` elements, with the `<img>` element inside the `<summary>` element, to create a disclosure component that reveals the longer description on request, as [the folks at Tetralogical suggest.](https://tetralogical.com/blog/2022/01/24/text-descriptions/)

The [WAI Images tutorial](https://www.w3.org/WAI/tutorials/images/complex/) provides a few more examples of ways to provide additional descriptions to images that I recommend checking out. The examples include providing a link to a separate page that contains the text presentation of the data in a chart, and using the `<figure>` element and providing the extended description in the figure’s `<figcaption>`.

```html
<!-- source: https://www.w3.org/WAI/tutorials/images/complex/#approach-3-structurally-associating-the-image-and-its-adjacent-long-description-html5 -->
<figure role="group">
  <img
    src="chart.png"
    alt="Bar chart showing monthly and total visitors for the first quarter 2014 for sites 1 to 3, described in detail below." />
  <figcaption>
    <h2>Overview</h2>
    <p>
      The chart shows the website hits for the
      first quarter of 2014 …
    </p>
    <h2>Values</h2>
    <table>
      <caption>
        Example.com Site visitors Jan to March
        2014
      </caption>
      <tr>
        …
      </tr>
    </table>
  </figcaption>
</figure>
```

When an image is neither unessential, nor an image of text, it is often used to “do something”, or to communicate information.

### Functional Images

An image whose purpose is to “do something” is a **functional image.**

Functional images are not _actually_ functional — meaning that they don’t actually _do_ something, because images are not interactive. Rather, they are typically used as labels for interactive elements like links and buttons.

In the following couple of sections, I’m going to assume that you’re using an `<img>` element inside your links or buttons, and am therefore going to discuss what the alt text of these images should be. Of course, as we learned in [the icon buttons chapter,](https://practical-accessibility.today/chapters/accessible-icon-buttons/) I always recommend using inline SVG whenever you need to implement icons and/or illustrations, as it is more flexible and adaptive in Forced Colors Modes, which we will learn all about in [another chapter.](https://practical-accessibility.today/chapters/forced-colors-mode/)

When an image is functional, its alt text should describe the function that it represents, not the image itself.

#### Images in links

**Images in links should describe the link destination, not the image’s contents.**

For example, a logo image would describe the destination of the logo, not the logo’s contents:

```html
<img
  src="path/to/logo.png"
  alt="The personal website of Jane Doe — Home" />
```

If the image in the link is sitting next to text, the browser will concatenate the alt text of the image with the text sitting next to it to compute the link’s accessible name.

For example, links that open in a new Window may include an icon that visually indicates that the link opens in a new Window. The icon thus communicates a piece of information that is relevant to the user. And its alt text should communicate the same information: that the link opens in a new window.

```html
<a
  href="https://www.w3.org/WAI/WCAG21/quickref/"
  target="_blank">
  How to meet WCAG Quick Reference
  <img
    src="path/to/window-icon.svg"
    alt="Opens in new window" />
</a>
```

The accessible name of the link that will be announced to the user is “How to meet WCAG Quick Reference, Opens in new window”.

If the icon is sitting next to text that already describes the link’s destination, and the icon thus no longer adds relevant information, the image is redundant and, as we mentioned in a previous section, its alt attribute should be empty to avoid unnecessary announcements. For example, the Twitter icon in this link.

```html
<a href="https://twitter.com/SaraSoueidan">
  <img src="/path/to/twitter-icon.png" alt="" />
  Follow me on Twitter
</a>
```

The accessible name of the link is “Follow me on Twitter”. The icon supplements the text visually, but does not communicate any additional relevant information. So, its alt attribute is left empty.

#### Images in buttons

**Images in buttons should describe the purpose of the button — i.e. the action that the button will initiate.**

For example, a maginfier icon used as a label for a Search button should describe the action initiated by the the button: Search; and a printer icon used as a label for a Print button should describe the action of the button: Print.

```html
<!-- do this -->
<img src="path/to/search-icon.svg" alt="Search" />
<!-- not this -->
<img
  src="path/to/search-icon.svg"
  alt="magnifier" />

<!-- do this -->
<img src="path/to/printer-icon.svg" alt="Print" />
<!-- not this -->
<img
  src="path/to/printer-icon.svg"
  alt="printer" />
```

The alt text of functional images **should describe the function they re``
present, not what they are.**

### Informative images

Informative images are images that communicate information that is essential or useful to understanding the content of the page. Examples of informative images include photographs of people, scenery or objects that add meaning to the content, or pictures of things such as products on an e-commerce website.

In the following sections, we’re going to discuss tips for crafting effective alt text for informative images.

## Best practices for crafting effective `alt` text for informative images

In order to serve the image’s equivalent purpose, the alt text should describe the information that the image is meant to communicate. This information is context-dependent. Where, how, and _why_ the image is used determines what information it should communicate.

> **One way to think of alternative text is to think about how you would read the page containing the image to someone over the phone, without mentioning that there is an image present. Whatever you say instead of the image is typically a good start for writing the alternative text.**
>
> [— HTML Living Standard](https://html.spec.whatwg.org/multipage/images.html#alt)

If you show an image to two people and ask them to give it an appropriate alt text, you are likely going to get two very different descriptions.

Regardless of what the exact alt text looks like, here are some things to keep in mind that will help you craft more effective and user-friendly image descriptions.

### Keep it short

Keep the alt text short and concise.

I know I said before that a picture is worth a thousand words. But not all pictures are _literally_ worth that many words in alt text.

How long the alt text should be will depend on how much information the image is meant to communicate in the context that it is in.

The general rule of thumb is that **the alt text should be as short as possible, but also as long as it needs to be.**

There is no character limit for alt text. So you can include as much information in it as the image needs. But beware that, according to [tests shared by Terrell Thompson](https://terrillthompson.com/tests/altlength.html), _"JAWS currently reads alt text in 125-character chunks (excluding spaces). If alt text exceeds 125 characters, it divides it into multiple graphics, each having no more than 125 characters of alt text, beginning where the previous graphic left off."_

This isn’t to say that your alt text can’t exceed 125 characters. It’s just something to keep in mind as you endeavour to keep it as short as possible, while ensuring it is as long as needed.

### End the alt text with a period

End the alt text with a period. This will make screen readers pause a bit after the last word in the alt text, which creates a more pleasant reading experience for the user. If the alt text is longer than one sentence, use punctuation where it is appropriate to avoid reading the alt text as one long, run-on string of text.

### Don’t mention it’s an image, unless it’s a relevant type

Semantics expose what something is. By using the <img> element, a screen reader will identify it as an image, and it will announce the role when the user focuses on it. For example, VoiceOver on macOS will “Image” right after it finishes reading the image’s alt text. Similarly, JAWS on Windows will say “graphic” at the end of the alt text. Whereas NVDA will start with “Graphic” followed by the content of the alt text.

Starting your alt text with “Image of” or “Photo of” is therefore redundant, and would add unnecessary announcements to what the screen reader user is hearing.

The exception to this rule is to mention when it’s a special type of image, like a sketch, illustration, or water color painting, to name a few examples, because this may help convey the style and nature of the image.

You may add the type of the image in this case either to the start of the alt text — for example, “Sketch of…”, “Water color painting of…”, or to the end of the alt text. For example:

```html
<img
  src="..."
  alt="A sketch of a bird-sized human in a bird cage. The human is yelling for help. A man-sized bird sits on a couch next to the cage. The bird is listening to the human making sounds, and says ‘if he is singing, it means he is happy.’" />
```

![A sketch of a bird-sized human caught in a bird cage. The human is yelling for help. A man-sized bird sits on a couch next to the cage. The bird is listening to the human making sounds, and says ‘if he is singing, it means he is happy.’](/markdown-assets/30.7.human-in-cage.webp)

### Context matters

The content of the alt text is context-dependent.

When you’re deciding how to describe the image in the alt text, you should consider what it is you’re trying to communicate through the image: are you using the image to communicate a certain emotion? or to highlight a product? or something entirely different?

You want to think about _why_ you are using a particular image in the context you are using it in.

Let’s go over a few examples.

This is a photo of a hummingbird standing on a small branch.

![A closeup of a hummingbird standing on a branch.](/markdown-assets/30.8.hummungbird-standing-on-a-branch.webp)
