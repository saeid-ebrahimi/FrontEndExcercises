In this chapter we’re going to discuss the accessible implementation as well as important usability considerations of two common mobile navigation patterns.

In both patterns, the mobile navigation is initially hidden; and it is shown when a navigation button is activated.

In the first pattern, when the navigation is shown, it takes up its natural place in the page’s layout.

In the second pattern, it slides out of the left side of the viewport like a drawer; and when it does, it overlays (and obscures) the page’s content.

## Hiding and showing the navigation using the navigation toggle

In the first pattern, when the JavaScript runs, the navigation is hidden, and a navigation button is presented to the user in its place.

The navigation button is typically implemented as an icon button. But to make our button more inclusive, we’re going to give it a visible text label, and we will hide the icon from assistive technologies using the `aria-hidden` attribute:

```html
<button>
  <svg
    height="21"
    viewBox="0 0 24 24"
    width="24"
    aria-hidden="true"
    style="color: inherit;">
    <path
      d="M3 13h18c0.552 0 1-0.448 1-1s-0.448-1-1-1h-18c-0.552 0-1 0.448-1 1s0.448 1 1 1zM3 7h18c0.552 0 1-0.448 1-1s-0.448-1-1-1h-18c-0.552 0-1 0.448-1 1s0.448 1 1 1zM3 19h18c0.552 0 1-0.448 1-1s-0.448-1-1-1h-18c-0.552 0-1 0.448-1 1s0.448 1 1 1z"
      fill="currentColor"></path>
  </svg>
  Navigation
</button>
```

When the button is activated, it toggles the visibility of the navigation. To communicate the state of the navigation (whether it’s expanded or collapsed), we will give the button an `aria-expanded` state attribute:

```html
<button
  class="nav-toggle"
  aria-expanded="[ true | false ]"
  hidden>
  <svg
    height="21"
    viewBox="0 0 24 24"
    width="24"
    aria-hidden="true"
    style="color: inherit;">
    <path
      d="M3 13h18c0.552 0 1-0.448 1-1s-0.448-1-1-1h-18c-0.552 0-1 0.448-1 1s0.448 1 1 1zM3 7h18c0.552 0 1-0.448 1-1s-0.448-1-1-1h-18c-0.552 0-1 0.448-1 1s0.448 1 1 1zM3 19h18c0.552 0 1-0.448 1-1s-0.448-1-1-1h-18c-0.552 0-1 0.448-1 1s0.448 1 1 1z"
      fill="currentColor"></path>
  </svg>
  Navigation
</button>
```

This all sounds familiar, doesn’t it?

**The navigation button is a disclosure widget.** A disclosure widget is a control (typically a button) whose sole purpose is to toggle the visibility of some content.

But this disclosure widget doesn’t toggle the visibility of just _any_ content. It toggles the visibility of the `<nav>` element, which exposes one of the most important landmark regions of the page.

```css
/* Hide the navigation when the aria-expanded state attribute is false */
.nav-toggle[aria-expanded="false"] + .site-nav {
  display: none;
}
```

## Hide the navigation list, not the landmark

As we’ve learned in [the landmark regions chapter,](https://practical-accessibility.today/chapters/landmark-regions/) using page landmarks is a fundamental way for screen reader users to access page content. And the navigation landmark is one of the first landmarks users look for on a page.

If the `<nav>` element is hidden, so is the landmark it exposes. As such, the landmark will no longer be reachable via screen reader shortcuts, and the user will not have **easy access** to its contents when they need it. For example, the navigation landmark will no longer be listed in the Landmarks list in VoiceOver’s Web rotor; nor in NVDA’s landmarks list. The user can, technically, still find the navigation through the navigation button, but that’s not how screen reader users typically navigate web pages.

"You see, users of [assistive technologies] don’t just start feverishly tabbing through an interface just hoping to find what it is they’re looking for, says accessibility engineer Scott O’Hara in his article “(Navigation) Landmark Discoverability” Well. Maybe they would if they were trying to prove a point about how horrible a site was coded. But yeah. Not really."

To avoid degrading the usability of the page, **you want the `<nav>` element and the landmark it exposes to remain persistent and reachable by landmark navigation.**

To do that, instead of hiding the `<nav>` element itself, you should hide **the content of the navigation**—whether that be the primary list element (`<ul>`) or a `<div>`— a container—surrounding multiple components of the navigation. In other words, the navigation button should control the contents of the navigation, not the navigation element itself.

So, when the navigation button is activated, the navigation landmark persists, and you show and hide the contents of the navigation instead.

Then, if you pull up the list of landmarks on the page, the navigation landmark will be exposed in the list, and the user can use landmarks shortcuts to find it and navigate to it more efficiently.

You should also **place the navigation button inside the navigation landmark.**
